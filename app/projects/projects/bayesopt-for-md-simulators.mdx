Coarse-Grained Molecular Dynamics (CG-MD) offers the possibility of modeling complex systems that might otherwise be impossible to simulate via finer-grained methods such as DFT and others. The key issue, however, is that the coarser we get, the more we care about larger, often new molecular structures that have never been parameterized or set up before. We are left to the mercy of tuning things by hand through trial and error. This is less than ideal; it couples CG-MD parameterization to a human expert, which is often (1) hard to reproduce and (2) slow.

In this post, I want to explore, through a minimal example, the implementation of an agentic framework to parameterize a biomolecule for CG-MD simulation straight from experimental measurements. The idea is that for unknown compounds, teams should be able to take a measurement of the new compound and use an agent to parameterize the CG-MD simulation to these measurements, thus resulting in a usable CG-MD parameterization grounded in experimental data.

## Optimization goal
To keep things computationally feasible, I chose the common biomolecule glycerol and decided to parameterize only the three Lennard-Jones terms — **bead size** (σ, ranging from 0.28 to 0.45 nm), **well depth** (ε, ranging from 1 to 8 kJ/mol), and **interaction cutoff** (ranging from 0.90 to 1.20 nm) — using two experimentally measured properties: the density of anhydrous glycerol at atmospheric pressure and 298.15 K (the temperature at which it was recorded[^1]), and its enthalpy of vaporisation [^2] [^3]. All other parameters (bond length, angle, bonded force constants, etc.) were left at their literature or standard values [^4]. 

Since the intention here is to demonstrate parameterization minimally from experimentally validated data points, the optimization problem is fitting our starting molecule to match the experimental density (1258.4 ± 0.86 kg/m³ at 298.15 K) [^1] and enthalpy of vaporisation (91 ± 1 kJ/mol) [^2] [^3]. This can be formally expressed by the following loss function:

$$
\text{loss} = \frac{1}{2} \left| \frac{\rho - \rho^*}{\rho^*} \right| + \frac{1}{2} \left| \frac{\Delta H_{\mathrm{vap}} - \Delta H_{\mathrm{vap}}^*}{\Delta H_{\mathrm{vap}}^*} \right|
$$



## The simulator

For simplicity, I use a purpose-built three-bead engine which maps each glycerol onto three beads, one per C–OH group at 30.7 u apiece, and simulates 125 of them. It runs at constant temperature and pressure (NPT) with a Berendsen thermostat and barostat to derive density and vaporisation enthalpy.


## The agentic framework

I'm aiming to have a portfolio of agents I can compare against each other. I want to compare (1) whether they are able to converge during minimization of the loss, and (2) how efficiently and reliably they are able to do this. This requires a shared surface from which I can fork various implementations.

```python
class BaseAgent:
    """Shared agentic loop for all agent types.
    ...
    """
    def __init__(self, config: AgentConfig, policy: Policy):
        """Initialize agentic loop."""
        self.config = config
        self._policy = policy

    def run(self) -> RunSummary:
        """Execute the optimisation loop and return a summary.

        Returns
        -------
        RunSummary
            Aggregated metrics for the completed run.
        """
        ...
        # Loop through simulation steps
        for step in range(1, self.config.n_steps + 1):
            params = self._policy.propose()
            ...
            # Simulate proposed parameters
            result = run_md_simulation(params, seed=self.config.seed)
            loss = result["loss"]
            ...

            # Update the policy with the run's loss
            self._policy.update(params, loss, ...)
            logger.log_step(step, params, result, best_loss, cumulative_cost)
            ...
        return summary
```

Now, as you can already see, our agentic surface above does not imply LLMs. This is intentional, as I want to make sure my portfolio of agents also contains simpler paradigms such as Bayesian Optimisation (BO), and we build in sophistication up to using LLMs, specifically Claude Opus 5, simply because it sat among the frontier reasoning models at the time of these runs [^5].

This is the agentic spectrum I decided to test:
- **BO**: one Gaussian Process over the scalar loss.
- **BO plus a feasibility model**: the same GP on the loss, fitted only on runs that
survived, plus a second GP over a 0/1 crash label. The latter improves BO's ability to navigate the feasibility threshold.
- **BO with an LLM warm-start**: seeds the GP/Bayesian optimiser with points proposed by the LLM before switching to standard Bayesian optimisation. This is an attempt to leverage the LLM's prior to shortcut the BO's exploration cold-start.
- **LLM (Claude Opus 5)**: the LLM proposes every parameter set, seeing the target values, the
bounds, and each previous run's parameters with its loss or its failure mode.

The four agents can branch out from the above abstraction by swapping out the policy where needed:

```python
from policies import FeasibleGPPolicy, BayesOptPolicy, LlmPolicy

class GPAgent(BaseAgent):
    ...
    def __init__(self, config: AgentConfig | None = None):
        ...
        policy = BayesOptPolicy(...)
        super().__init__(config, policy)

class FeasibleGPAgent(BaseAgent):
    ...
    def __init__(self, config: AgentConfig | None = None):
        policy = FeasibleGPPolicy(..., warm_start=None)
        super().__init__(config, policy)

class GPAgentLLMWarmStart(BaseAgent):
    ...
    def __init__(self, config: AgentConfig | None = None):
        # Load the n_initial data points initially suggested by the LLMAgent
        warm_start = load_cache()[config.seed or 0][: config.n_initial_random]
        policy = BayesOptPolicy(..., warm_start=warm_start)
        super().__init__(config, policy)

class LlmAgent(BaseAgent):
    ...
    def __init__(self, config: AgentConfig | None = None):
        policy = LlmPolicy(
          model=config.llm_model, effort=config.llm_effort)
        super().__init__(config, policy)
```

BO versus LLM-based approaches differ clearly in how they traverse the optimization landscape. While BO needs to spend a large portion of its simulation budget building a prior, an LLM already implicitly carries a prior from its pretraining phase, resulting in a more intentional optimization process. 

This is not to say that BO methods don't earn their keep! BO in tandem with the feasibility model—though needing ~30 simulations—eventually builds a fine prior over the optimization landscape, allowing it to close much of the gap to the LLM-based approach, albeit less effectively.

## Visualizing the results

Since this is a CG-MD parameterization exercise, let's look at the three-bead system being parameterized by our agent, and how the final parameterization behaves in an actual CG-MD simulation. 

Looking at the three-bead system at its first, middle, and final proposals, it's actually the level of cohesion among beads that changes: bead size moves by under 20%, while well depth moves by up to 75% (i.e., the visible change is the hue rather than the radius of the bead).

Finally, simulating the fitted system over 0, 30, and 60 picoseconds shows a disordered, voided slice with beads exchanging neighbours; this is the behavior of a liquid, not a lattice. It is also visibly too mobile: beads travel 0.29–0.43 nm rms over those 60 ps, about one bead diameter, where a real glycerol molecule would cover some 0.02 nm in the same window [^7] — the fitted models diffuse one to two hundred times too fast. This is a limitation of this study, where I'm focusing on the agentic setup to parameterize a glycerol stub three-bead system.

## Conclusions

In this blogpost I went through a demonstration of using an agentic framework for parameterizing a stub glycerol molecule to match its experimental data. The aim of this experiment is to understand whether agentic frameworks can let us more speedily configure new molecules in CG-MD when all we have is an experimental target, in this case density and vaporisation enthalpy of glycerol. 

I found out that indeed both Bayesian Optimization and, more directly, LLMs are able to parameterize the glycerol stub when slotted into an agentic framework next to a CG-MD simulator. With Claude Opus 5 being the clear winner, though using BO + a feasibility model is a competitive approach, considering that it doesn't involve any API spending.


| agent | sims × seeds | median best loss, re-measured on unseen seeds | API spend |
| --- | --- | --- | --- |
| Bayesian optimisation | 40 × 12 | 0.0741 | — |
| BO + feasibility model | 40 × 12 | 0.0645 | — |
| BO + LLM warm-start | 40 × 12 | 0.0590 | $0.65 |
| LLM (Claude Opus 5) | 20 × 12 | **0.0347** | $8.56 |


## Future work
Finally, as I've noted along this write-up, two things need to be swapped out in order for the output of this agentic framework to be physically usable in CG-MD pipelines:
1. Swap the custom-built simulator for GROMACS or LAMMPS: this will let the agentic framework interface with standard simulation pipelines.
2. Swap the stub bead glycerol model for one resulting from an all-atom simulation.
